# 分析报告工作台 Web 产品需求

## 文档控制

- 产品：分析报告工作台 Web
- 状态：approved
- 版本：1.4
- 负责人：项目所有者
- 批准人：用户
- 批准时间：2026-07-28T07:13:14Z
- 权威位置：`docs/PRD.md`

## 目的

让旧版 Web 的客户报告、客服接单、会话和补充资料形成可靠、可追踪且互不串档的云端服务闭环，同时保持旧账号和旧数据兼容。

## 用户与问题

客户通过旧版 Web 上传报告和资料；客服在独立工作台接单、查看进度并沟通。现有实现存在待接单漏收、资料进度错误、会话删除后异常恢复、补充资料不同步或跨客户残留，以及新账号 UID 强度不足的问题。

## 目标

- 报告上传成功后，客服工作台必然出现且只出现一个对应待接单工单。
- 客户资料状态在客户与客服界面一致，并且不同报告档案互不污染。
- 客服隐藏当前会话的结果可靠，新客户消息到达时能够明确重新开启。
- 每个新注册用户获得不可预测、不可变且唯一的 UID。
- 旧版信用报告详情能够解释分数来源，并让总览、风险、评分、负债、查询和账户各自呈现独立内容。
- 首页指标进入对应报告上下文，热点默认折叠；旧版报告和本地状态在报告、案件与登录账号之间严格隔离。
- 唯一客户端形态为浏览器 Web；仓库和发布链路不再保留 Android、iOS、原生 App 或小程序运行时、安装包和平台发布入口。
- 每个对外发布的征信数字都能追溯到报告页内证据、规范化事实和确定性公式；证据不足或关系冲突时停止给出伪精确结论。

## 非目标

- 不迁移或重写现有用户 UID。
- 不物理删除历史会话或历史资料审计记录。
- 不修改或部署服务器上的最新版本项目。
- 不在本任务中改变现有账号等级、银行老师权限或管理员审计权限。
- 不取消手机浏览器响应式、安全区、触屏交互和浏览器文件上传能力。
- 不在本阶段建设完整多 OCR 引擎、人工复核工作台、生产级工作流编排或迁移历史分析结果。

## 约束与边界

- 新字段和新行为必须兼容没有 `caseId` 的旧报告、旧会话和旧材料。
- 同一报告的重试或并发请求不能创建重复客服工单。
- 新报告默认建立独立资料档案；旧档案只在历史上下文中可见，不自动带入。
- 当前会话被客服隐藏后，只有晚于隐藏时间的真实客户消息可以使其重新出现。
- 固定测试账号保留现有确定性 UID；普通新账号使用强唯一 UID。
- “客户端、客服端、银行老师端、管理员端”只表示同一 Web 系统中的权限视图，不表示独立原生应用。
- 官方 PDF 内容作为业务原始事实来源；系统仍必须验证页数、页序、读取完整性和字段证据，不把“官方”误解为“解析一定无缺失”。

### REQ-WEB-ONLY-CLIENT-SURFACE

- 陈述：旧版项目只提供浏览器 Web 客户端和与其隔离的 legacy API；必须删除 Android、iOS、原生 App、小程序的运行依赖、选择器、推送分支、安装包基线和发布宣传。
- 理由：消除多端残留造成的构建分叉、错误发布和维护歧义，确保当前源码在不同电脑上得到同一套 Web 行为。
- 优先级：must
- 依赖：none

#### 验收标准

- AC-WEB-001：仓库不存在 Android、iOS、小程序平台目录或 APK/AAB/IPA 安装包及其来源基线。
- AC-WEB-002：Web 依赖和生产源码不包含 Capacitor、Cordova、原生文件选择插件、小程序订阅或 App 推送运行分支。
- AC-WEB-003：PDF/图片选择、multipart 上传、本地存储、Hash 路由、浏览器返回键和手机浏览器安全区继续可用。
- AC-WEB-004：构建只产出可部署到旧版静态 Web 空间的资源，并继续固定调用独立 `/legacy-api`。
- AC-WEB-005：自动化边界测试会在原生平台目录、原生运行依赖或安装包基线重新出现时失败。

#### 边界情况

- iPhone、iPad 和 Android 浏览器仍属于 Web 支持范围；UA 与安全区判断不能当作原生端代码删除。
- 旧数据若记录历史推送渠道，只能作为已停用历史字段兼容展示，不得重新启用原生或小程序能力。

## 需求

### REQ-SERVICE-WORKFLOW-RELIABILITY

- 陈述：报告保存成功时，服务端必须按报告建立幂等客服待接单工单；客服工作台必须可靠展示所有可接或已由本人接取的服务工单。
- 理由：避免客户已提交报告但客服无任务可处理。
- 优先级：must
- 依赖：none

#### 验收标准

- AC-SVC-001：同一 `reportId` 重复触发三次，只存在一个客服工单。
- AC-SVC-002：产品匹配三方会话仍能进入客服工作台，不被银行通道预过滤。
- AC-SVC-003：慢请求、交叠轮询或单次网络失败不得用旧结果覆盖新列表，也不得清空最后一次成功列表。

#### 边界情况

- 没有客户姓名时仍可用 UID 和报告 ID 建立工单。
- 旧会话缺少新增字段时继续按原有通道兼容读取。

### REQ-CONVERSATION-HIDE-REOPEN

- 陈述：客服删除聊天框表示对该客服隐藏当前会话视图；隐藏必须立即持久化，只有之后到达的真实客户消息可以重新开启并明确标记。
- 理由：保证删除操作稳定，同时不丢失客户后续求助和管理员审计记录。
- 优先级：must
- 依赖：REQ-SERVICE-WORKFLOW-RELIABILITY

#### 验收标准

- AC-CHAT-001：删除成功后，交叠的旧轮询响应不能恢复聊天框。
- AC-CHAT-002：服务重启后隐藏状态仍然有效。
- AC-CHAT-003：隐藏后客户发送新消息，聊天框重新出现并带有“客户新消息重新开启”状态。

#### 边界情况

- 客服本人或系统消息不得触发重新开启。
- 消息与隐藏时间接近时使用服务端单调顺序字段判定，而不是只依赖客户端时间。

### REQ-CASE-MATERIAL-SYNC

- 陈述：每份报告建立唯一 `caseId`；补充材料按 `uid + caseId` 保存，只同步到该档案对应的客服工单和服务进度。
- 理由：防止新客户继承旧客户资料，并保证客服端看到客户刚提交的材料。
- 优先级：must
- 依赖：REQ-SERVICE-WORKFLOW-RELIABILITY

#### 验收标准

- AC-MAT-001：客户上传材料后，对应客服工单立即可见并显示“待确认”。
- AC-MAT-002：材料被确认后，“资料”进度节点显示完成；需补充或重传时显示对应警示。
- AC-MAT-003：档案 A 与档案 B 使用相同材料类型时仍相互隔离。
- AC-MAT-004：旧材料保留在旧档案中，但不自动复制到新档案。

#### 边界情况

- 旧材料没有 `caseId` 时只在旧版兼容档案中读取，不批量复制到新档案。
- 没有可解析报告 ID 时使用服务端生成的独立兼容 `caseId`。

### REQ-IMMUTABLE-UNIQUE-UID

- 陈述：密码注册和短信自动注册必须通过同一个 UID 生成器创建不可预测、不可变且唯一的用户标识。
- 理由：UID 是报告、消息和材料归属的核心键，必须避免碰撞和手机号耦合。
- 优先级：must
- 依赖：none

#### 验收标准

- AC-UID-001：普通新账号 UID 使用 `usr_` 前缀和 UUID 随机源，不能从手机号推导。
- AC-UID-002：写入前验证 UID 未被占用；发生碰撞时重新生成而不是覆盖旧用户。
- AC-UID-003：密码注册、短信自动注册、登录、刷新和当前用户接口返回同一个 UID。
- AC-UID-004：现有用户及固定测试账号 UID 不发生迁移或变化。

#### 边界情况

- 并发注册不同手机号不得产生重复 UID。
- 同一手机号并发注册仍只允许创建一个账号。

### REQ-LEGACY-REPORT-EXPLAINABILITY

- 陈述：信用报告详情只保留一个顾问入口；当前总分必须同时展示可复算的规则、输入和证据，只有数值而没有完整依据的历史评分只能作为不可核验存档；总览右侧的每个分类选项卡必须展示各自内容；风险摘要通过选择器一次聚焦一个风险组。
- 理由：减少重复操作，避免用户把无法解释的分数或重复内容当成正式结论。
- 优先级：must
- 依赖：none

#### 验收标准

- AC-RPT-001：底部只有一个“咨询顾问”主按钮，不再同时出现“问顾问”。
- AC-RPT-002：总分旁可查看评分来源、维度贡献或证据不足说明，展示分数与依据使用同一可信来源。
- AC-RPT-003：总览、风险、评分、负债、查询和账户选项卡分别展示对应内容，不能复用同一页面占位。
- AC-RPT-004：风险摘要的三个风险组可通过下拉选择，所选项、数量和明细保持一致。
- AC-RPT-005：`assessment-stored`、`legacy-explicit` 等缺少可复算扣分链的历史评分不进入当前可信总分、风险等级、产品匹配或顾问建议；页面显示“待评估”并可单独说明历史值不可核验。
- AC-RPT-006：只有同时具备明确名称、分子、分母、公式版本和输入证据的比率才能作为权威指标展示；`总负债 ÷ 总授信额度` 如需展示必须称为“授信占用率”，不得冒充一般负债率。

### REQ-LEGACY-HOME-NAVIGATION

- 陈述：首页债务、逾期和近六月查询指标必须进入对应报告分类或债务上下文；信用热点位于右上角且默认折叠。
- 理由：让首页每个入口符合标签含义，并把资讯从主任务流中降级。
- 优先级：must
- 依赖：REQ-LEGACY-REPORT-EXPLAINABILITY

#### 验收标准

- AC-HOME-001：总债务、逾期账户和近六月查询三个入口具有不同的目标分类参数。
- AC-HOME-002：最近债务进入真实报告与债务上下文，不生成不存在的债务编号。
- AC-HOME-003：热点默认不占用首页内容区，用户可在右上角展开和收起。

### REQ-LEGACY-REPORT-DATA-ISOLATION

- 陈述：旧版 Web 必须兼容旧报告的 CV2、蛇形字段和共享额度标记，并按登录会话、报告及案件隔离分析、债务、凭证、材料、消息和本地缓存。
- 理由：防止旧报告显示错误的信用卡使用率或负债，更要防止切换账号、重复上传或并发请求造成跨客户串档。
- 优先级：must
- 依赖：REQ-CASE-MATERIAL-SYNC

#### 验收标准

- AC-ISO-001：已用额度 5,000、授信额度 10,000 的人民币信用卡显示 50% 使用率；外币账户不进入人民币求和，共享额度只有原文明示关系、稳定关系标识或人工裁决时才合并，同机构、同开户日或币种组合不能证明共享。
- AC-ISO-002：只有账户外壳而 CV2 聚合负债为 50,000 时保留聚合值；全部明确结清或排除时显示 0。
- AC-ISO-003：报告、债务执行、复核凭证、同步队列和材料不得跨报告或案件匹配。
- AC-ISO-004：账号 A 的请求、令牌刷新或上传在切换到账号 B 后即使晚到成功，也不得覆盖、清理或向 B 重传 A 的数据。
- AC-ISO-005：同一客户端报告编号只允许相同内容恢复或重试；不同内容复用该编号必须冲突失败。

### REQ-EVIDENCE-FIRST-CREDIT-ANALYSIS-V2

- 陈述：DeepSeek 只产生候选原始事实；服务端把文档页清单、页内证据、规范化事实和确定性派生指标分层保存，并为每个权威数字提供可机读的证据与公式引用。
- 理由：同一份官方征信报告的结果必须稳定、可解释、可复核；模型自述完整、缓存命中或温度为 0 都不能代替证据链和确定性计算。
- 优先级：must
- 依赖：REQ-LEGACY-REPORT-DATA-ISOLATION

#### 验收标准

- AC-EV-001：每次新分析生成有序 `DocumentManifest`；每条可用证据至少包含页码和文本 span，当前读取器无法提供几何坐标时明确标记为不可用，不伪造 polygon。
- AC-EV-002：`CreditFactLedger` 明确区分 `accepted`、`unknown`、`absent`、`not_applicable` 和 `conflict`；关键 `accepted` 事实必须引用实际文档证据，明确为 0 不得与未识别或未记载混淆。
- AC-EV-003：信用卡使用率、查询次数、负债和评分由确定性规则产生；每个派生指标携带公式 ID、版本、输入事实 ID 和业务状态，同时保留旧版 Web/API 既有字段。
- AC-EV-004：共享额度只接受原文明确标记、稳定关系标识或人工裁决；同机构、同开户日或币种组合只能形成冲突候选，不能自动合并。若冲突会跨越评分阈值，则停止发布单点使用率和评分。
- AC-EV-005：冻结输入与实现版本后，绕过缓存重复运行得到相同 `evidence_hash`、`fact_hash` 和 `metric_hash`；时间戳、运行 ID、耗时和传输态不进入业务哈希。
- AC-EV-006：证据覆盖、文档完整性或关键事实门禁失败时返回明确失败/待复核状态，不能进入权威缓存；上下文、日志和测试证据不得保存原始报告、姓名、证件号、卡号或模型密钥。
- AC-EV-007：账户状态采用规范语义而不是子串命中；“未逾期”“无逾期”“从未逾期”不得产生逾期或异常事实，明确逾期天数与权威结构化字段优先。
- AC-EV-008：贷款与查询机构分类使用 `bank`、`non_bank`、`unknown` 三态并保留显式来源；无法确认的机构保持 `unknown`，不得默认归入非银或触发非银评分扣分。
- AC-EV-009：查询窗口统一以报告日为锚点，采用日历月并包含起止边界；API、规则引擎和 Web 不得分别使用滚动 30/90/180/365 天口径。
- AC-EV-010：旧报告没有证据化公式的评分或比率不具备 `decisionEligible` 资格，兼容读取不得升级为 evidence-v2 权威结果。

#### 边界情况

- 相同机构、日期和原因的合法重复查询必须保留为不同事实，不能按内容去重。
- 纯外币账户没有报告明确人民币等值金额时单列，不参与人民币使用率或负债求和。
- 旧缓存和旧报告继续按 `deterministic-v1` 兼容读取；只有满足 v2 门禁的新结果才声明 `evidence-v2` 权威能力。
- 原生文字 PDF 当前只有页码与字符 span 时可以形成可追溯证据；精确坐标必须等读取器真实提供后再写入。

## 用户旅程

客户上传并保存报告后，系统建立唯一客服工单和资料档案；客服接单后可查看该档案的授权材料和进度。客服隐藏会话后列表保持稳定，如客户后来发送新消息，系统明确重新开启。新注册账号从第一次创建起使用永久 UID 关联以上所有记录。

## 成功指标

- 幂等报告建单重复测试：重复工单数为 0。
- 客服轮询稳定性测试：旧响应覆盖次数为 0，单次失败列表清空次数为 0。
- 跨档案材料隔离测试：泄漏或错误关联数为 0。
- UID 并发生成测试：碰撞数为 0。
- 报告详情契约测试：重复顾问入口数为 0，六个分类均有独立内容。
- 旧版数据回归：50% 使用率、共享额度去重、CV2 聚合负债与明确结清样本全部通过。
- 账号切换并发回归：旧会话结果写入或清理新会话次数为 0。
- Web-only 边界回归：原生运行依赖、平台源码目录和安装包基线重新引入次数为 0。
- 证据链回归：权威关键事实缺少证据引用次数为 0，五种事实状态发生混淆次数为 0。
- Fresh-run 回归：同一冻结输入绕过缓存至少 5 次，三个业务哈希不一致次数为 0。
- 共享额度回归：仅凭机构与开户日自动合并次数为 0，纯外币错误计入人民币汇总次数为 0。

## 依赖与外部批准

- 本任务只形成仓库代码与本地验证结果；部署、启用和线上业务验证需要单独授权。

## 风险与开放问题

- 旧数据缺少 `caseId`，只能通过兼容读取保留，不能在没有可靠客户身份的情况下自动归并。
- 当前存储为进程内状态加同步持久化；更高并发规模仍需未来评估事务型数据库。
- 当前 PDF/OCR 链路没有统一输出精确 polygon；本阶段如实保存页码、span 与几何不可用状态，不以虚构坐标换取表面完整率。
- 外部模型别名可能被供应商原地升级；在模型快照不可冻结前，只能承诺规则与账本层的哈希确定性，不能宣称模型候选事实可跨时间完全重放。
